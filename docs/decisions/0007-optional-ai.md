# 0007 — Optional AI with free and personal-key routes

Carry's encrypted handoff and Continue work without AI. AI is a separate opt-in disclosure on a received card. The browser shows the exact goal, next action, note, excerpt, and link title/URLs it proposes to send, plus fixed instructions. Pressing Help me resume only opens this preview. Pressing **Approve and ask AI** makes one request. Neither route fetches linked pages or saves generated text on the relay.

**Free assistance from Carry** sends those approved plaintext fields through an authenticated Carry API route to OpenRouter and a free model provider. The API checks that the authenticated device is the recipient of an unexpired envelope in an active pair, validates the input and size, and keeps only daily request counts. The API also receives the card ID to authorize the request. It does not store plaintext, plans, or the shared key in Turso. The shared key is read from the API-only `CARRY_OPENROUTER_FREE_KEY` environment variable. The browser build never contains it. Five requests per device and 50 per service per UTC day bound usage; an IP limit also applies. Free assistance fails closed when the key is absent. The first request uses `openrouter/free`; on 408, 429, or selected 5xx errors the API may try at most two catalog-listed `:free` models. It never retries with a paid model. A bad response, exhausted quota, or unavailable model leaves Continue usable.

**My OpenRouter key** is configured in one AI settings screen through OAuth S256 PKCE or manual entry. The user-owned key stays in origin-scoped browser IndexedDB (`carry-ai-v1`) until Disconnect or site-data clearing. Every received card on that browser profile can use it without another paste. This route calls OpenRouter directly from the browser and never puts the personal key or approved text in a Carry API request. The default model is `openrouter/free`; a different model requires explicit selection and may charge the user's account. There is no paid fallback. The OAuth callback code is removed from the URL before normal app requests.

The browser validates the returned JSON shape, length, and link URLs against the disclosed links, and requires the model to acknowledge missing task context. Model output remains untrusted text rendered by React. Free requests expose approved plaintext to the Carry API as well as OpenRouter and its chosen provider; the personal route exposes it to OpenRouter and its provider. Neither route sends before approval. Browser-side storage and encryption do not protect against a compromised web build or malicious same-origin script.

The referenced [ContextVM chat PR #29](https://github.com/ContextVM/contextvm-site/pull/29) informed the free-model rotation. Its browser-embedded shared key is deliberately not copied. Keys pasted into a chat or committed to a public repository should be revoked and replaced before deployment. Automated tests use fake keys and mocked OpenRouter responses; live availability and account limits need a deployed-origin check.
